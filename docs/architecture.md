# Architecture

Mermaid source: [`architecture_diagram.mmd`](architecture_diagram.mmd) (paste into https://mermaid.live or any Mermaid viewer) and [`database_erd.mmd`](database_erd.mmd).

## 1. Overview
Q-assist AI is a layered Python application. The UI (Streamlit) only calls **services**; services call **domain modules** (safety, NLP, RAG, LLM, workflows); everything that touches SQLite goes through **one repository**.

| Layer | Modules | Responsibility |
|---|---|---|
| UI | `app.py`, `src/ui/*` | Pages, forms, charts. No business logic. |
| Voice | `src/voice/*` | Browser mic widget + text-to-speech controls. |
| Services | `src/services/*` | `ReceptionistService` (one user turn), `ConversationService` (sessions), `EvaluationService`. |
| Safety | `src/safety/*` | Deterministic urgent/injection/medical-advice rules and fixed messages. |
| NLP | `src/nlp/intent_classifier.py` | Rule-based intent label, reason, workflow, escalation flag. |
| RAG | `src/rag/*` | Load → chunk → embed → store → retrieve → threshold. |
| LLM | `src/llm/*` | Prompt builder, Gemini service, deterministic demo responder. |
| Workflows | `src/workflows/request_router.py` | Simulated request logging/status. |
| Data | `src/database/*` | ORM models, engine, repository (all SQL), init/seed/reset. |
| Config | `config/settings.py` | Environment-driven settings with safe defaults. |

## 2. Journey of one question (text or voice)
1. **UI**: the user types, or speaks (browser transcribes; transcript lands in an editable box). Pressing *Send* calls `ReceptionistService.handle(question, history, conversation_id)`.
2. **Validate**: empty or over-long input returns a friendly message (not stored).
3. **Safety first**: `check_urgent` runs deterministic regexes. A match returns the fixed 999/NHS 111 message, flags escalation and **never calls retrieval or the LLM**.
4. **Injection check** on the user text (declines "ignore your instructions…" style input).
5. **Intent**: `classify_intent` returns label, rule-match count, reason, workflow, escalation flag. Human requests and medical-advice requests get fixed responses.
6. **Retrieval**: the question is embedded and compared with indexed chunks (cosine). If the best score is below the threshold the app returns the "could not verify" fallback — again without an LLM call. Genuine follow-ups ("How long does it take?") may borrow the previous user message if the question alone fails.
7. **Prompt**: `build_prompts` loads the versioned system prompt, trims history, wraps sanitised chunks in `<retrieved_document>` tags.
8. **Answer**: `LLMService.generate` calls Gemini. On any failure (no key, bad key, rate limit, timeout, network, malformed) it returns `mode="demo"` with an error kind, and `demo_responder` builds an extractive answer labelled "Demo mode … not generated by an LLM".
9. **Workflow**: `route_request` chooses a *simulated* request type/status.
10. **Persist**: `Repository.record_interaction` stores messages (redacted), intent, sources, request, escalation. A DB failure never breaks the chat.
11. **Display**: answer, intent badge, status, escalation indicator, source panel. *Read aloud* uses browser speech synthesis.

## 3. Prompt construction
See `docs/prompt_engineering.md`. The user message = recent history + delimited documents + question; the system prompt is `prompts/receptionist_system_prompt.txt`.

## 4. Configuration and secrets
Everything comes from environment variables (optionally `.env`, which is git-ignored). `GEMINI_API_KEY` is read only in `config/settings.py`/`llm_service.py`, never logged, never stored in the DB and never shown in the UI (only "key set: yes/no").

## 5. Error handling and fallback modes
| Failure | Behaviour |
|---|---|
| No API key / any LLM error | Demo mode, clearly labelled; reason shown in details panel |
| Embedding model unavailable | TF-IDF keyword fallback, note shown on Settings/KB pages |
| Bad/empty/scanned document | Skipped with a warning; other files still indexed |
| Empty knowledge base | Fallback answers; app keeps running |
| Database unavailable | Banner; chat works, nothing saved |
| Browser lacks speech APIs | Widgets explain; typing always works |
